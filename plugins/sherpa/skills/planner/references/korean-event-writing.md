# 한국어 캘린더 이벤트 작성 지침

이 문서는 이벤트를 새로 만들거나 제목·설명을 고칠 때 적용한다. 날짜가
과거인지 미래인지는 제목의 문체를 바꾸지 않는다. 캘린더 날짜가 시점을
나타내고, 제목은 그날의 일정만 가리킨다.

## 작성 순서

1. 이벤트와 미리알림을 구분한다. 약속·방문·배송·결제처럼 날짜나 시간이
   고정된 일은 이벤트로, 사용자가 수행하고 완료 처리할 일은 미리알림으로
   만든다.
2. 출처에서 날짜·시간·고유명사·제품명·수치·URL을 뽑는다. 확인되지 않은
   값은 추정하지 않고 `확인 필요`로 둔다.
3. 정확한 캘린더를 고른다. 공유 캘린더나 비슷한 이름을 임의로 선택하지
   않는다.
4. 아래 제목 규칙으로 초안을 쓴다.
5. 필요한 근거만 설명에 구조화한다. 제목과 같은 문장을 되풀이하지 않는다.
6. 한국어 검사기를 통과시킨다. 오류는 모두 고치고 경고는 문맥을 확인한다.
7. 생성 후 제목·날짜·시간대·캘린더·알림·반복·설명을 다시 읽는다.

## 제목의 시제

제목은 `대상 + 행위` 또는 `기관·상품 + 일정명`으로 쓴다. 문장이 아니라
짧은 명사구를 기본으로 삼는다.

| 피할 표현 | 쓸 표현 |
|---|---|
| ○○전자 냉장고 배송 완료 | ○○전자 냉장고 배송·설치 |
| 로봇청소기 설치 예정 | ○○전자 로봇청소기 설치 |
| 로봇청소기 사전 점검 완료 | 로봇청소기 사전 점검 |
| 카드 대금이 결제될 예정 | 카드 대금 결제 · 카드명 |
| 대출 원리금이 출금됨 | 대출명 정기 상환 |
| 관리비를 확인해야 함 | 관리비 명세서 확인 |
| 프로모션이 시작되었음 | 카드 프로모션 제공 시작 |

`완료`, `완료됨`, `했음`, `되었음`, `예정`, `진행 예정`은 생성한 제목에
쓰지 않는다. 과거 날짜를 뒤늦게 기록해도 같은 원칙을 적용한다. 완료 여부를
관리해야 하는 일은 제목을 바꾸지 말고 미리알림의 완료 상태를 사용한다.

출처가 붙인 공식 행사명이나 작품명에 해당 표현이 들어 있으면 고유명사로
보존한다. 이 예외는 출처가 정확한 공식 명칭을 증명할 때만 적용한다.

## 자연스러운 한국어

- `배송이 진행될 예정입니다`처럼 피동과 예정 표현을 겹치지 말고 `배송`으로
  줄인다.
- `설치와 관련하여 확인` 같은 번역투를 피하고 `설치 확인`처럼 바로 쓴다.
- `진행`, `처리`, `사항`, `관련`, `해당` 같은 만능 명사를 불필요하게 붙이지
  않는다.
- `매우 중요한`, `원활한 진행을 위한` 같은 수식은 근거가 없으면 뺀다.
- 같은 뜻을 제목과 설명에서 반복하지 않는다.
- 이모지, 장식용 따옴표, 과도한 괄호와 구분 기호를 새로 넣지 않는다.
- 가운데점은 같은 층위의 대상이나 행위를 묶을 때만 쓴다. 긴 제목을 기계적인
  병렬 목록으로 만들지 않는다.
- 고유명사·제품명·모델명·날짜·금액·회차·인용·URL은 문체를 다듬는다는
  이유로 바꾸지 않는다.

## 설명 작성법

설명은 회고 문장보다 `항목: 값` 형식을 우선한다. 사실을 보태되 제목의
시제를 바꾸지 않는다.

```text
일정일: 2030-05-20
대상 제품: 로봇청소기
사전 점검일: 2030-05-10
구매처: ○○마트 ○○점
방문 시간: 별도 안내 확인
근거: ○○전자 배송센터 카카오톡 안내
```

`사전 점검 완료`는 `사전 점검일: 날짜`로, `설치가 완료되었음`은
`설치일: 날짜`로 바꾼다. 계정·자동납부처럼 일정 밖의 실제 상태는
`자동납부 상태: 연결`처럼 상태값으로 적을 수 있다. 상태값을 이벤트 제목에
올리거나 완료 서술로 풀어 쓰지 않는다.

조건과 변동 가능성은 현재형으로 짧게 쓴다. 예를 들어 `비영업일이면 다음
은행 영업일에 출금`, `방문 시간은 별도 안내 확인`처럼 적는다. 근거 없는
권고나 감상은 넣지 않는다.

## 이벤트 유형별 제목

| 유형 | 형식 | 예시 |
|---|---|---|
| 배송·설치 | 기관 + 대상 + 행위 | ○○전자 냉장고·오븐 배송·설치 |
| 방문·예약 | 대상 + 방문·진료·상담 | 치과 진료 |
| 금융 | 상품 + 결제·상환·확인 | 주택담보대출 정기 상환 |
| 통신 | 상품 + 청구·약정 만료 | 인터넷 요금 청구 |
| 행정 | 대상 + 신청·제출·수령 | 민생 소비쿠폰 신청 |
| 점검 | 대상 + 점검·검사 | 로봇청소기 사전 점검 |

## 생성 전 검사

- 날짜가 과거라는 이유로 제목을 완료형으로 바꾸지 않았는가.
- 날짜가 미래라는 이유로 `예정`을 덧붙이지 않았는가.
- 제목이 피동문이나 완전한 보고 문장이 아닌가.
- 고유명사·날짜·수치·URL이 출처와 같은가.
- 설명은 짧은 라벨과 값으로 읽히는가.
- 추측, 번역투, 과장, 중복, 불필요한 장식이 없는가.
- 알림은 사용자가 요구했을 때만 추가했는가.
- 생성 또는 수정 뒤 네이티브 재조회가 일치하는가.
